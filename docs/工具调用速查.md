# 工具调用速查

两批升级已完成部署与运行加载验收。以下参数按已部署源码核对，读取收据对应 continuity 1.3.1，视频概览对应 video-studio 1.5.2-lian.1。它们是**参数示例，没有在小涟的私有资料上执行**。每块 JSON 对应前面注明的工具名；尖括号内容必须换成上一步真实返回值。工具加载状态与可用版本以实际运行环境为准。

## 找回原话

`whale_life_memory`：
```json
{"action":"search","query":"罐子、角度、看不清条件","limit":5}
```

对话命中优先复制返回的 `sourceContextAction`。等价参数形式：
```json
{"action":"context","id":"<搜索返回的 chat: ID>","before":2,"after":2,"chars":3600}
```

展开记录：
```json
{"action":"get","id":"<结果中的 id>","offset":0,"chars":2400}
```

下一页使用返回的续读偏移，不自行猜页码。上下文最多返回 6000 字符，来自已归档的原消息；不是全会话承诺，不产生新授权。

## 如何看新读取收据

输入参数不变，不需要自行填写 callId。加载 1.3.1 后：

- search 的 readReceipt.kind 为 preview；只说明展示了多少内容，不持久记次数、不升温。
- get/context 的 readReceipt.observations 列出实际返回范围；coverage 为 empty、fragment 或 whole-document。whole-document 只代表本次全文返回，不证明理解；不累计多个请求的片段。
- 有真实宿主调用 ID 时，同一次请求重试不重复记收据。换参数或来源已变化会要求新请求；缺少 ID 时 deduplication 为 unavailable，不冒充已去重。
- context 收据不改变原有冷藏排序；get 保留既有非空打开规则，手动 cold/core/favorite 选择不被重写。冷藏不是删除。

需要确认加载情况时，用现有 whale_continuity：
```json
{"action":"status"}
```

第二批验收应看到 pluginVersion 为 1.3.1 且 readingSemantics.version 为 1。磁盘文件已经改好不能单独证明运行进程已加载。

## 只为需要延续的工作做记录

`whale_task_board` 新任务：
```json
{"action":"update","title":"代码练习一：动作与节奏","status":"pending","next":"先完成5至10秒样段"}
```

修改已有任务先 `get`，再携带其 `id` 与 `expectedVersion`。新任务参数不要直接套到已有任务上。

`whale_context_pack`：
```json
{"action":"checkpoint","summary":"<真实结论、原文事件或文件定位、尚未解决问题>","taskIds":[],"noteIds":[]}
```

这里只是续接摘要；重要原文保留可回查位置。

## 一个代码视频项目

`whale_video_project`：
```json
{"action":"create","name":"代码练习一_动作与节奏"}
```

`whale_video_render` 分别调用：
```json
{"action":"preview","project":"<create 返回的 project>"}
```
```json
{"action":"render","project":"<create 返回的 project>"}
```
```json
{"action":"technical","project":"<create 返回的 project>"}
```
```json
{"action":"frames","project":"<create 返回的 project>","times":[0,6,12,18,23]}
```

秒数必须在该作品有效范围内。此工具的 `frames` 渲染当前项目，不证明旧 MP4 的内容。使用完预览可调用：
```json
{"action":"close-preview"}
```

## 先看一段视频概览

已部署版本在原有 `whale_video_render` 下的 `overview`，先指定已授权的本地视频：

```json
{"action":"overview","file":"<实际本地 MP4 的绝对路径>","start":0,"end":20,"cells":9}
```

按实际时长调整起止秒数；这段示例适合至少 20 秒的视频。它返回采样宫格、真实绝对时码、来源哈希和 `analysisId`，用于决定哪里值得细看，不代表连续看完整片。

同一会话可以回查某一格的独立原帧；格号要使用结果中的实际编号，下面仅示例第 5 格：

```json
{"action":"overview","analysisId":"<上次返回的 analysisId>","cellId":5}
```

回查不同时传新文件或新时间范围。原片已变或会话不符时会拒绝旧分析，不能把旧帧当当前成片。需要看动作时，沿返回的 `watchArgs` 或 `biliPerceiveArgs` 使用对应既有工具；没有给出参数就不要猜。若 `attachmentStatus` 为 `failed`，说明分析已保存但图片尚未交付，使用返回的 `retry` 回取同一分析。

## 核对实际导出的影片

`whale_film_evidence` 先建立预期表；下列十秒样段只是教学题目：
```json
{"action":"prepare","label":"动作练习样段","rows":[{"id":"shot-1","start":0,"end":5,"text":"","visual":"物件靠近障碍并停下","motion":true},{"id":"shot-2","start":5,"end":10,"text":"","visual":"物件换一种动作尝试通过","motion":true}]}
```

再指向真实 MP4：
```json
{"action":"frames","plan":"<prepare 返回的 plan>","file":"<实际 MP4>","offset":0,"limit":4}
```

看过返回图片后记事实：
```json
{"action":"observe","report":"<frames 返回的 report>","observations":[{"rowId":"shot-1","observation":"<实际看到的内容；不能照抄预期当作观察>"}]}
```
```json
{"action":"check","report":"<frames 返回的 report>"}
```

分页沿返回的 `range.nextOffset`。计划是意图，图片才是证据；`motion:true` 会采相邻时码，但仍不代替连续播放。

## 审稿与声音按需使用

`whale_creative_review`：
```json
{"action":"prepare","project":"<真实项目路径>","stage":"script"}
```
```json
{"action":"prepare","project":"<真实项目路径>","stage":"film"}
```

填写 prepare 返回的文件，再检查：
```json
{"action":"check","project":"<真实项目路径>","report":"<prepare 返回的 file>"}
```

脚本应填当前正文中的精确引文；成片应填实际时码和观察。通过只说明记录与版本符合要求，不是自动审美评分或渲染强制闸门。

`whale_audio_check`：
```json
{"action":"check","file":"<实际 MP4 或音频>","expectedText":"<当前版本旁白原稿>","language":"zh"}
```

`whale_listening`：
```json
{"action":"listen","file":"<实际 MP4>","start":0,"end":30,"question":"描述实际听到的声音、停顿和突兀变化。"}
```

区间按实际文件长度调整。后者由本地音频模型提供观察；主模型不要据此冒充人类直接听见或把识别结果当作审美结论。无声音的练习不用强行添加这些步骤。
