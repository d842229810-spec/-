# 安装指南

## 兼容环境

本快照来源于 Windows 上的 DeepSeek Harness 0.2.1-rc.3。建议准备 Node.js 24、Python 3.11/3.12 和 Git。桌面控制仅支持Windows。视频模块另需FFmpeg/FFprobe和对应渲染环境。

## 1. 下载

下载仓库ZIP并解压，或运行：

~~~powershell
git clone https://github.com/d842229810-spec/-.git lian-plugins
cd lian-plugins
node tools/verify-release.mjs
~~~

## 2. 生成本地配置副本

仓库源码使用以下示例路径，不是安装后的真实位置：

- E:/DSH：Harness安装根目录。
- E:/LianHome：助手工作目录。
- E:/CenHome：Codex联络助手工作目录，仅通信插件需要。
- C:/Users/USER：示例用户目录。
- session-00000000-0000-0000-0000-000000000000：需要配置的所有者会话占位符。

先生成一个新的、尚不存在的本地输出目录：

~~~powershell
node tools/configure.mjs --output ./local-build --harness-root "E:/DSH" --lian-home "E:/LianHome" --cen-home "E:/CenHome"
~~~

脚本只生成副本，不修改正在运行的插件或profile，不启动网络服务、不安装依赖。实际路径不同就替换参数。需要所有者会话的插件可加 --owner-session "session-你的真实会话ID"；未填写时保留占位符，不能投入有归属控制的实际使用。真实配置副本不要上传GitHub。

## 3. 准备依赖

按 docs/依赖与运行时.md 配置所需模块。保留 harness-plugins 内的层级与“扩展”目录：部分插件通过相对路径共享life、视频和感知模块。

lian-video-runtime 的 package.json 固定了Remotion依赖，在该目录运行 npm ci。Python依赖在插件对应 requirements.txt/锁定列表中；使用独立虚拟环境，不把现有环境整个复制到仓库。

## 4. 接入Harness

先备份当前profile、插件目录和数据目录，停止相关写入者；首次接入使用独立测试profile。将本地生成副本里的所需模块放到配置中的对应插件位置。

若目标Harness版本支持本地file包，可通过其插件管理器选择本地包；命令行支持的常见格式为：

~~~powershell
dsh plugin --profile desktop add "@local/lian-continuity@file:E:/DSH/插件/扩展/lian-continuity"
~~~

这是需要按本机路径、目标profile和目标CLI支持情况调整的示例；仓库整理阶段未重新执行该安装命令。务必使用正在运行应用所对应的CLI，避免PATH指向旧版dsh。

检查 package.json 的入口、导出与 cordis.patch.yml。部分本地集成包没有标准bundle patch，不能套用同一条命令：工作区菜单依赖客户端模块，工作区管理器需要独立配置，Codex通信桥还需要连接文件。没有适配目标Harness版本前不要整包覆盖生产profile。

Cordis patch里的name用于匹配模块，不是指定一个新文件路径就能替换已加载代码。修改磁盘文件后，需要确认目标进程实际重新加载；同一进程的ESM缓存可能仍引用旧文件。

## 5. 逐项验收

先查看加载错误、插件版本、真实工具schema。然后用状态工具、合成临时文件和无账号的样例核对。最后才配置QQ、浏览器登录和收费模型。

这批源码不是统一的一键安装产品；通用安装向导、跨版本SDK适配、模型自动下载和QQ扫码登录不在本发布包内。遇到错误先查看对应插件使用指南与原始README，勿通过删除私人数据来“修复”。

## 回退

退出相关写入进程，恢复安装前的插件和profile备份，再启动并核对加载状态。不要用源码仓库覆盖实际聊天记录、账本或记忆库。不要用历史备份悄悄覆盖安装之后产生的新资料。
