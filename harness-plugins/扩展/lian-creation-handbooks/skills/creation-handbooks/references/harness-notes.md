# Harness 与现有工具的衔接

## 当前任务优先

按用户当前明确选择和项目已有记录决定模型、渠道、分辨率、时长与声音。使用真实可用的工具和账号；旧手册的模型名称、API 示例和教学画质不代表当前账号已开放的选项，也不自动覆盖新决定。

## 方法与工具分工

文学、视觉和视频手册负责内容设计、提示词与返修。现有 `dafeiyu-video-production` 描述本机制作路线，`lian-creative-quality` 处理当前作品审稿和审美反馈；需要时按实际注册情况使用图像、TTS、FFmpeg、视频生成和B站感知工具。技能数据本身不调用付费模型，不另装生成服务。

用户只要方案时交付完整文字；用户要求实际制作，且已有工具与授权支持时继续制作。写出提示词、提交生成和拿到成片是不同状态。保留实际生成任务编号，状态不明时先查旧任务，避免重复付费。

## 参考与素材

上传、绑定和生成分别核对。桌面文件可在当前授权范围实际读取；云端生成服务不能仅凭 Windows 本地路径获取文件。按真实素材标识和槽位安排身份、服装、动作、空间和声音，不虚构已绑定。

教学里的 480P 或模型版本只属于示例。支持首尾帧、编辑或延长的真实渠道分别使用对应模式，不能只在提示词写字段就宣称已经完成设置。

## 项目与反馈

使用项目当前有效剧本、资产、镜头初末态和已认可作品；用户更改时重查相关依赖。作品、参考、审稿和续接资料放在用户授权的项目位置，技能目录只存方法资料。

沿用已有本地记忆与项目记录机制，不新增一套并行的人格或记忆系统。原包的 Python 工程工具已经有一份旧副本，本次只整合创作知识与只读入口，没有把那些脚本宣称为已验收的审美判断或自动发布工具。

## 平台资料

视频与视觉手册中的官方文档链接是相应方法的参考资料。遇到实际工具能力或界面差异时，核对当前入口和任务模式；不要把另一产品的 API 字段当当前平台按钮。

## Remotion本地制作

代码视频使用lian-remotion-production，素材一致性使用lian-media-library，文稿与成片证据复看使用lian-script-film-review。whale_video_project创建项目，whale_video_render负责preview/frames/render/technical，whale_media_assets检索及打包参考，whale_creative_review核对审稿版本。新项目位于E:/LianHome/工作室/Remotion影片。实际环境与版本看whale_video_status，官方细节按需用whale_video_reference读取。

这组工具不自动替GPT或Updream上传、绑定或生成，不以技术检查替代实际观感。沿用既有项目需求与发布规则。
